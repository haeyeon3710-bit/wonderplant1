## 1단계 — 구조 분석과 연결 확인 (2026-10-14)

### 확인한 기존 구조

- 프레임워크 없는 HTML/CSS/JavaScript 정적 사이트. `scripts/build-board.cjs`가 목록·글·사이트맵·`_redirects`·체험 데이터를 생성합니다.
- Netlify는 GitHub `main`의 변경을 받아 빌드하며 저장소 루트를 배포합니다. 기존 `/login`, `/adm`, `/adm/new`, `/adm/edit`, 한글 `/blog/{slug}`는 `_redirects`로 연결됩니다.
- 초안과 글 사본은 localStorage의 `wonderful-admin-demo-v1`에 배열 JSON으로 저장됩니다. IndexedDB는 사용하지 않습니다. 이미지 파일은 체험 상태에서 base64 Data URL로 들어갑니다.
- 체험 로그인은 sessionStorage의 `wonderful-admin-demo-session`이며 실제 Supabase Auth 세션은 아닙니다.
- 폼 → `readForm()` → `repository.save()` → localStorage가 현재 저장 흐름입니다. 미리보기는 현재 폼과 블록을 DOM으로 렌더링하며, JSON 내보내기는 현재 폼 데이터를 다운로드합니다. DB/API 호출이 없어서 공개 사이트 발행은 이루어지지 않습니다.
- 공개 두 글은 루트 원본 HTML, 카드 설명은 `content/card-descriptions.json`, 글별 분류는 `content/post-categories.json`, 공통 카테고리는 `categories.js`입니다. 게시글당 카테고리 한 개입니다.
- 카테고리: 임플란트 / 고난도 임플란트 / 전체 임플란트 / 의식하진정법 / 치아교정. 교체 시기 글은 임플란트, 출혈 글은 고난도 임플란트입니다.

## 2단계 — DB·RLS 생성 및 적용 완료

- `cms-images`는 비공개 버킷이며 이미지 파일당 20MB, PNG/JPEG/WebP/GIF만 허용합니다. 초안 이미지의 익명 읽기는 금지하고 발행 글에 연결된 파일만 공개 읽기를 허용합니다.

- 테스트는 트랜잭션 롤백으로 끝났습니다. 테스트 후 Auth 사용자·게시글은 0개, 실제 카테고리 5개와 저장소 한도 20971520바이트를 확인했습니다. Supabase 보안 Advisor 경고 0개.

- `202610140005_public_blog.sql` 실제 적용: 이전 슬러그 이력과 공개 조회 RPC. 슬러그 변경 시 이전 주소는 현재 발행 주소로 연결되며 비공개 글의 이력은 공개되지 않습니다.

- 실제 DB의 `cms_public_blog.sql` 트랜잭션 검사: 공개 글/분류/환경 분리, 최신·인기 정렬, 12개 페이지, 주소 변경·비공개 이력 검사 통과 후 롤백.
- `check-public-render.cjs` 실제 DB SSR 검사 한 차례 통과: 기존 두 글의 본문·목차·발행일·카테고리·한글 주소·메타데이터·사이트맵, 비공개/없는 글 404, 이전 주소 301.
- 최종 UI·조회수 조정 후 `check-public-render.cjs` 실서버 재검사도 통과했습니다. 앞선 자동 승인 검토 오류는 이후 정상 검증으로 해소됐습니다. 최신 관리 UI의 Netlify 배포 종합 검증은 8단계에서 수행합니다.

## 6단계 — 조회수 DB 집계 구현 및 부분 검증

- `202610140006_post_statistics.sql`, `202610140007_bridge_policy.sql`을 실제 DB에 적용했습니다. 조회 기록·한국 시간 일별 합계·누적 카운터를 한 트랜잭션에서 변경합니다. 게시글 행 잠금으로 동시 요청을 직렬화하고 같은 방문자의 최근 30분 기록이 있으면 증가하지 않습니다. 조회 변경은 글의 수정일·버전을 바꾸지 않습니다.
- 공개 집계는 발행 글과 활성 카테고리만 반환하며 최근 7일(오늘 포함)·최근 30일(오늘 포함) 정렬과 순위를 제공합니다. preview/production 자료는 모든 집계에서 구분합니다.
- `supabase/tests/cms_statistics.sql` 실제 DB 검사 통과 후 롤백: 중복 제한/만료, 일별·기간별 합계, 발행 상태·환경, 변경일/버전 보존, 익명과 일반 사용자의 카운터 변경·관리자 통계 읽기 거절, 관리자 요약.
- `lib/views.mjs`, Netlify `cms-views.mjs`, Supabase `cms-view/index.ts`, `post-views.js`: Netlify가 제공하는 연결 IP와 User-Agent를 서버 비밀값으로 HMAC 처리합니다. 원래 IP/User-Agent는 DB나 Supabase로 전송하지 않습니다. 관리자 세션 쿠키가 있는 요청과 알려진 봇은 집계에서 제외합니다. 같은 IP/브라우저 정보의 방문자는 30분 동안 함께 집계될 수 있습니다.
- 조회수 전용 연결 값의 해시는 비공개 스키마에만 저장하며, 기록 RPC는 service_role만 실행할 수 있습니다. Netlify에는 전체 DB 접근 키를 두지 않습니다. Edge Function은 별도 비밀값 검증을 사용하므로 플랫폼 JWT 검사 대신 사용자 정의 인증을 수행합니다.
- `check-views.cjs`, `check-view-edge.cjs` 로컬 검사 통과: 고정 환경, 보호된 카운터/시각, 안정적인 해시, IP·관리자/봇 처리, CSRF와 인증 실패·서버 장애 처리. 전체 배포 번들 검사에 공개 렌더링/조회수 함수를 추가했습니다.
- 사용자 승인 후 조회수 전용 비밀값을 Netlify의 Deploy Preview 한 곳에만 등록하고 검증 해시는 DB에 저장했습니다. `cms-view` Edge Function도 배포했습니다. 처음 동시 요청용 운영 자료 생성 시도는 실행되지 않았고 운영 자료는 생성되지 않았습니다. 실제 검증은 preview 전용 임시 글로 수행했습니다.
- `scripts/check-view-live.cjs` 실제 Edge 검사 통과: 비밀값 없음/불일치 거절, 익명 직접 RPC 실행 거절, 동일 방문자 동시 8개 요청을 1회 계산, 서로 다른 8개 요청 모두 반영, 카운터 총 9회와 수정일/버전 보존. Netlify의 상세 페이지 전체 연결은 8단계에서 확인합니다.
- 보안 Advisor의 RLS 무정책 알림은 service_role 전용 명시적 읽기 정책으로 처리했습니다. 별도의 유출 비밀번호 검사 알림은 Supabase Pro 이상 기능이므로 Free 요구사항에 따라 유료 업그레이드는 하지 않았습니다. 근거: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

## 7단계 — 관리자 목록과 DB 관리·통계 연결

- `lib/admin-data.cjs`, `cms-management`, `admin/management.js`, 기존 `adm.html`·`app.js`: 전체 글/조회수/오늘/7일/30일 요약, 상태·카테고리 필터와 검색, 글별 조회수, 최근 발행 글, 기간별 인기 순위, 일별 통계를 실제 DB와 연결합니다.

- `check-management.cjs`, 관리자 DOM 검사: 통계/기간 순위, 카테고리 저장/오류, 상태 필터, 기존 분류 보존 검사 통과. `cms_categories_management.sql` 실제 DB 검사도 통과 후 롤백했습니다. 일반 사용자 분류 쓰기 거절, 관리자 생성·수정·비활성/활성 복구, 공개 노출 제어와 원래 다섯 분류 보존을 확인했습니다.
